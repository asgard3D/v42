# V1.01.40 — Mage Pose Live Sync

## Problem
The V1.01.35 Mage arm JSON could be visible in the 3D adjustment preview, while the actual in-game Character Model V2 still used the old saved neutral arm profile. The old save data had no arm-adjustment schema marker, so loading it replaced the intended Mage baseline.

## Fix
- Treat the user's V1.01.35 Mage JSON as the authoritative Mage baseline for old saves.
- Migrate old saves once to adjustment schema 2.
- Persist `armWeaponAdjustSchema: 2` so later manual edits are preserved.
- Apply the same configured arm pose to the live Character Model V2 and the adjustment preview.
- Preserve walk/attack animation as an offset from the configured pose.
- Do not replace the Character Model V2 or weapon assets.

## Mage baseline
- armL position: `(-0.04, -0.07, -0.02)`
- armL rotation: `(0.59, -1.52, 0)`
- armR position: `(0.02, -0.03, 0)`
- armR rotation: `(-1.81, -0.75, 0)`
- weaponL: `(0,0,0)` position/rotation
- weaponR: `(0,0,0)` position/rotation

## Expected result
The actual in-game Mage should match the desired adjusted appearance shown in the user's reference image, instead of returning to the neutral arms shown in the second image.
