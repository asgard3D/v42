# V1.01.23 — Three.js Legacy Renderer Boundary

## Goal
Begin rapid Three.js separation without changing the proven game behavior.

## Changes
- Added `engine/three-legacy-adapter.js` as the single migration-layer owner for direct Three.js renderer bootstrap.
- Engine Bridge now resolves its legacy Three.js API through `AsgardThreeLegacy` instead of directly owning the global engine reference.
- Runtime resolves Three.js once through the adapter; gameplay code still behaves exactly as before.
- Render Adapter color/shadow constants now resolve through the legacy adapter.
- PlayCanvas and existing fallback paths are unchanged.

## Not removed yet
- The Three.js CDN is still loaded because the current runtime still uses Three.js classes extensively for legacy world construction.
- This milestone deliberately avoids deleting those classes until the world/character object factories have migrated.

## Next separation target
Move runtime object construction (geometry/material/light/world/character factories) behind renderer-neutral bridge calls, then remove the runtime's direct Three.js class usage in batches.
