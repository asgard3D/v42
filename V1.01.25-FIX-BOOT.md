# V1.01.25 — Renderer Bootstrap Boundary FIX-BOOT

## Issue
The first V1.01.25 build moved the main renderer DOM mount and Clock construction into the adapter. The game then remained on the WebGL bootstrap screen.

## Fix
The proven V1.01.24 main startup path is restored in `js/asgard-runtime.js`:
- direct renderer DOM mount
- direct `new THREE.Clock()`

The new adapter APIs remain available as passive boundaries for a later migration, but they are not used during boot in this version.

## Preserved
- Character Model V2
- first-person hat-top camera
- first-person character visual hiding
- PlayCanvas bridge
- map/gameplay/combat systems
- all V1.01.24 behavior

## Validation
- `node --check js/asgard-runtime.js`
- `node --check engine/render-adapter.js`
- `node --check engine/three-legacy-adapter.js`
